# Feature Specification: Internationalization and Localization

**Feature Branch**: `[feature-i18n]`
**Status**: Implemented
**Input**: `src/i18n.sh`, `test/i18n.bats`, `docs/i18n.md`, and `example/i18n_ops.sh`

## Problem Statement *(mandatory)*

A script written with this library can only speak English, and can only write numbers, money, sizes, and dates the way one country writes them. Every attempt to fix that by hand runs into the same three walls.

The first is grammar. Choosing between "1 file" and "5 files" with a test for `count == 1` is correct in English and wrong nearly everywhere else: Russian needs a different form at two than at five, and a different one again at twenty one; Arabic has six; Vietnamese has one. A script that pluralizes by counting to one produces text that reads as broken to the people it was translated for.

The second is that the obvious tools lie. Asking `date` for a month name under `LC_TIME=de_DE.UTF-8` works only if that locale has been generated on the machine, and when it has not — which is the normal case in a container — `date` does not fail. It answers in English. In the same way, `printf '%.2f'` follows `LC_NUMERIC`, so the same script prints `1234.50` on one machine and `1234,50` on another, and on a machine missing the locale it also writes a warning to standard error while appearing to succeed. Both failures are silent and both are machine-dependent.

The third is that there was nowhere to put the strings. `dybatpho::file_size` reports a raw byte count, `src/date.sh` never sets a message locale, and no module had a notion of a catalog, a fallback, or a text direction.

## Business Value *(mandatory)*

- Let one script serve users in their own language without forking it per language.
- Produce numbers, money, sizes, and dates that are correct for the reader rather than for the author.
- Make the output independent of which locales happen to be installed on the machine, so a container and a workstation agree.
- Give translators a file format their existing tools already write, and a way to be told what they have missed.
- Keep all of it free of `jq`, `gettext`, `bc`, and `awk`, so that wanting translations does not add a dependency.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Show a message in the user's language (Priority: P1)

As a script author, I want to write my user-facing strings once and have them appear in the reader's language so that I do not maintain a copy of the script per language.

**Why this priority**: Everything else in the module supports this, and without it the rest has no purpose.

**Independent Test**: Write two catalogs, run the same calls under each locale, and verify the output differs and the values are interpolated.

**Acceptance Scenarios**:

1. **Given** a catalog for a locale, **When** a key is translated, **Then** the text for that locale is returned
2. **Given** a message containing `{name}`, **When** a binding is supplied, **Then** the value replaces the placeholder
3. **Given** a value containing an ampersand or a backslash, **When** it is substituted, **Then** it appears exactly as given
4. **Given** a key no catalog carries, **When** it is translated, **Then** the key itself is returned and the script continues

---

### User Story 2 - Count things in a language with its own grammar (Priority: P1)

As a script author, I want the right plural form chosen for me so that a translated message reads correctly in languages whose rules differ from English.

**Why this priority**: This is the part an author cannot reasonably get right by hand, and getting it wrong is visible to every reader.

**Independent Test**: Ask for the category of the same counts in several languages and verify each follows its own rule, in particular that Russian and Polish disagree at twenty one.

**Acceptance Scenarios**:

1. **Given** a count and a language, **When** the category is requested, **Then** it follows that language's rule rather than English's
2. **Given** a catalog with plural forms, **When** a count is translated, **Then** the form for its category is used
3. **Given** a catalog missing the category a count selected, **When** it is translated, **Then** the `other` form is used rather than the key
4. **Given** a count above the grouping size, **When** it is substituted, **Then** it is grouped the way the locale groups digits

---

### User Story 3 - Write numbers, money, and sizes for the reader (Priority: P1)

As a script author, I want values formatted the way the reader's locale writes them so that a report is readable rather than merely correct.

**Why this priority**: These appear in almost every script that reports anything, and the machine-dependent failure modes make hand-rolling them unsafe.

**Independent Test**: Format the same value under several locales and verify the separators, grouping, symbol placement, and decimal count each follow the right source.

**Acceptance Scenarios**:

1. **Given** a number and a locale, **When** it is formatted, **Then** the group and decimal marks are that locale's
2. **Given** an Indian locale, **When** a large number is formatted, **Then** it is grouped by lakh rather than by thousand
3. **Given** an amount and a currency, **When** it is formatted, **Then** the decimal count comes from the currency and the symbol placement from the locale
4. **Given** a negative amount with a leading symbol, **When** it is formatted, **Then** the sign appears before the symbol
5. **Given** a shell whose numeric locale uses a comma, **When** a number is formatted, **Then** the output is unchanged

---

### User Story 4 - Write dates without depending on the machine (Priority: P1)

As an operator, I want dates and times in my language whether or not the machine has my locale installed, so that output does not silently revert to English.

**Why this priority**: The silent fallback is the failure this module exists to prevent, and it cannot be detected by the caller.

**Independent Test**: Format a fixed timestamp for a locale while forcing a hostile time locale on the shell, and verify the names are still that locale's.

**Acceptance Scenarios**:

1. **Given** a timestamp and a locale, **When** it is formatted, **Then** the field order and names are that locale's
2. **Given** a shell forced to the C time locale, **When** a German date is formatted, **Then** the month name is still German
3. **Given** a pattern containing quoted text, **When** it is rendered, **Then** the letters inside the quotes are literal rather than fields
4. **Given** a locale on a twelve hour clock, **When** midnight is formatted, **Then** it reads twelve rather than zero

---

### User Story 5 - Find out what has not been translated (Priority: P2)

As a maintainer, I want to be told which keys a translation is missing and which have lost a placeholder, so that an incomplete translation is caught before a user sees it.

**Why this priority**: It is what keeps the catalogs correct over time, but the module is usable without it.

**Independent Test**: Compare a deliberately incomplete catalog against a reference one and verify both the absent key and the renamed placeholder are reported.

**Acceptance Scenarios**:

1. **Given** a source tree, **When** keys are extracted, **Then** every literal key is written as a template entry
2. **Given** a call whose key is built from a variable, **When** keys are extracted, **Then** the call site is reported rather than guessed at
3. **Given** a translation missing a key, **When** it is checked, **Then** the key is reported as missing
4. **Given** a translation whose placeholder was renamed, **When** it is checked, **Then** the difference is reported

### User Story 6 - Translate the parts of the CLI the author never wrote (Priority: P2)

As a script author, I want the help, prompts, banners, and parser errors that the library itself prints to appear in the reader's language, so that translating my own strings does not leave half the screen in English.

**Why this priority**: A CLI whose descriptions are translated but whose `Usage:`, `Options:`, and `Unrecognized option:` are not reads as half-finished; it is a completion of Story 1 rather than a separate capability.

**Independent Test**: Translate the library's own keys in a catalog, run a generated help and a rejected switch, and verify both appear in the target language while the default run is unchanged.

**Acceptance Scenarios**:

1. **Given** a catalog carrying the library's own keys, **When** help is generated, **Then** the headings and placeholders appear in that language
2. **Given** an unrecognized switch, **When** the parser rejects it, **Then** the message is translated and still names the switch
3. **Given** a count of positional arguments, **When** the parser rejects it, **Then** the plural form is the target language's rather than English's
4. **Given** none of that is turned on, **When** anything above runs, **Then** the output is byte for byte what it was before the module existed

---

### Example Workflow

```bash
. dybatpho/init.sh --modules i18n

DYBATPHO_I18N_PATH="${PWD}/locale"
dybatpho::i18n_init vi_VN

printf '%s\n' "$(dybatpho::i18n_t deploy.start app=api env=production)"
printf '%s\n' "$(dybatpho::i18n_tn deploy.files 1240)"
printf '%s\n' "$(dybatpho::i18n_currency 1234.5 VND vi_VN)"
printf '%s\n' "$(dybatpho::i18n_date "$(dybatpho::date_now)" full vi_VN)"

dybatpho::i18n_lint --reference en vi_VN || exit 1
```

## Edge Cases

- A source tree with a subdirectory or file the process cannot read.
- A script formats a date, a time, or a relative time against the clock without having loaded the `date` module.
- A locale tag written in the BCP-47 style, with a script, a codeset, or a modifier.
- The C locale, which is a request for untranslated output rather than a language.
- A number wider than a machine word, and a rounding carry that lengthens the integer part.
- A translated value containing an ampersand, a backslash, a percent sign, or a newline.
- A catalog whose last line has no trailing newline.
- A gettext entry that is fuzzy, obsolete, untranslated, or spread over several lines.
- A gettext header whose plural expression is hostile.
- A message id that is a whole English sentence rather than a short key.
- A translation call captured in a command substitution, which runs in a subshell.
- A locale for which only some of the data is present.
- A library message whose English text carries a value, so that it cannot serve as its own message id.
- A library string counted in a language whose plural rules disagree with the English the call site built.
- A hook reached from a child shell that inherited the exported function without the module's internals.
- A percentage, amount, size or counted message is asked for with a value that is not a number.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: The active locale MUST be resolved from an explicit setting first, then from `LC_ALL`, `LC_MESSAGES`, `LANG`, and `LANGUAGE`, and MUST accept both the POSIX and BCP-47 spellings of a tag.
- **FR-002**: The C and POSIX locales MUST be treated as a request for untranslated output: the key is returned, nothing is recorded as missing, and strict mode does not stop the script.
- **FR-003**: A lookup MUST walk a fallback chain that drops the region before the script and ends at the configured fallback locale, so that a partial translation is backed by a more general one.
- **FR-004**: A translation MUST substitute `{name}` and positional placeholders without using a pattern substitution, so that a value containing an ampersand or a backslash survives on every supported release of Bash.
- **FR-005**: An unbound placeholder MUST be left visible in the output rather than removed.
- **FR-006**: An untranslated key MUST return the key itself and succeed by default, and MUST stop the script only when strict mode is on.
- **FR-007**: The plural category MUST be chosen by the rules of the language the consulted catalog is written in, not of the language originally asked for.
- **FR-008**: A plural lookup MUST fall back from the selected category to `other`, and then to a plain translation of the same key.
- **FR-009**: Catalogs MUST be readable in a native `key = value` format and in the GNU gettext `.po` format, without requiring `jq`, `gettext`, `bc`, or `awk`.
- **FR-010**: A `.po` entry that is fuzzy, obsolete, or has an empty translation MUST NOT be treated as a translation.
- **FR-011**: The plural expression in a `.po` header MUST NOT be evaluated; the built-in rules decide the category, and the declared form count is used only to map positional entries onto named categories.
- **FR-012**: A malformed entry in a catalog MUST stop the caller rather than being skipped.
- **FR-013**: A catalog MUST be loaded at most once per shell, and resetting MUST clear every catalog, the resolved locale, and the recorded misses.
- **FR-014**: Numbers MUST be formatted by manipulating digit strings rather than through `printf '%f'`, so that the result does not vary with the shell's numeric locale and an integer wider than a machine word is exact.
- **FR-015**: Grouping MUST be driven by per-locale data supporting a secondary group size, so that Indian locales group by lakh.
- **FR-016**: Rounding MUST go half up, and MUST NOT print a negative zero.
- **FR-017**: The number of decimal places MUST come from the currency and the symbol placement and digit grouping from the locale, and a negative amount MUST place its sign outside a leading symbol.
- **FR-018**: An unknown currency MUST warn and fall back to the code as its symbol rather than stopping the script.
- **FR-019**: Byte sizes MUST be computed with integer arithmetic that cannot overflow at the top of the range, and MUST support both the 1024 and 1000 based standards.
- **FR-020**: Month names, weekday names, and date patterns MUST come from data this module owns, and `date` MUST be consulted only for numeric fields and only under a fixed locale.
- **FR-021**: Text inside single quotes in a date pattern MUST be literal, and an unsupported pattern field MUST stop the caller by name.
- **FR-022**: Relative time strings MUST come from the catalog so that they can be translated, and MUST route their counts through the plural rules and the number formatter.
- **FR-023**: The direction of a locale MUST be reported, and helpers MUST be provided to isolate text of unknown direction and to strip those markers again.
- **FR-024**: Locale data MUST be extendable at run time, and each registration MUST reject malformed input when it is registered rather than when it is used.
- **FR-025**: Key extraction MUST report a call site whose key is not a literal instead of guessing, and MUST emit the plural categories of the target language.
- **FR-026**: Checking a translation MUST report keys that are missing or empty and placeholders that differ from the reference, and MUST NOT report a key carried only as plural forms as missing.
- **FR-027**: The library's own diagnostics MUST be translatable using their English text as the message id, and that translation MUST be off by default so that output is unchanged unless it is asked for.
- **FR-028**: User-visible text the library composes with a value in it — a parser error naming a switch, a rejected argument count — MUST be translatable through a stable key, with the English rendering the call site already built used whenever the key is untranslated.
- **FR-029**: A library string that counts something MUST take the plural form of the target language, not the one the English call site chose by testing for one.
- **FR-030**: The chrome `cli` prints — help headings, usage placeholders, prompts, and parser errors — and the banners `logging` composes before boxing them MUST pass through the same hook as the diagnostics.
- **FR-031**: Every such hook MUST be guarded on an internal helper of this module, so that it stays inert in a child shell that inherited only the exported functions, and MUST NOT add a dependency edge from `cli` or `logging` onto this module.
- **FR-032**: Loading the module MUST NOT load `date`. `i18n_date`, `i18n_time`, `i18n_datetime`, `i18n_date_pattern`, and `i18n_relative` when it has to read the clock MUST stop the script, naming the `date` module and how to load it, when that module is not loaded; catalogs, plurals, numbers, and a relative time against a given reference MUST work without it.
- **FR-033**: `i18n_percent`, `i18n_currency`, `i18n_bytes`, `i18n_tn` and `i18n_library_plural` MUST format their number in the caller's shell, so a value or precision that `i18n_number` refuses stops the call, naming the function the script called, instead of printing what was left.
- **FR-034**: A catalog key that cannot be stored MUST be reported under the public function that loaded or registered it.
- **FR-035**: `i18n_datetime` MUST read the timestamp in the caller's shell, so that one it cannot read stops the call under its own name instead of printing an empty date and time.
- **FR-036**: Scanning sources MUST warn about every directory or file it cannot read and keep scanning the rest, rather than stop or skip it silently.

### Key Entities *(include if feature involves data)*

- **Locale**: A language, optionally with a script, a region, and a modifier.
- **Catalog**: A set of translations for one locale, read from a file.
- **Message key**: What a translation is looked up by, which may be a short identifier or a whole sentence.
- **Plural category**: One of `zero`, `one`, `two`, `few`, `many`, `other`.
- **Locale data**: The number symbols, currency layout, names, and date patterns of a locale.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: The same script produces correct text in a language whose plural rules differ from English, without the author knowing those rules.
- **SC-002**: Formatted output is identical on a machine with no locales generated and on one with many.
- **SC-003**: A translator can work in the file format their existing tools already produce.
- **SC-004**: An incomplete or damaged translation is reported before a user sees it.
- **SC-005**: Adding the module changes nothing about what an existing script prints.
- **SC-006**: A CLI built on the library presents its help, its prompts, and its parser errors in the reader's language without the author restating any of that text.

## Integration Tests *(mandatory)*

- **IT-001**: Normalize POSIX, BCP-47, modified, and C locale tags, and reject a string that is not a locale.
- **IT-002**: Verify the resolution order across the explicit setting, `LC_ALL`, `LC_MESSAGES`, and `LANG`.
- **IT-003**: Verify the fallback chain drops the region before the script, and that the C locale has none.
- **IT-004**: Translate a key under two locales and verify each returns its own text.
- **IT-005**: Verify named, positional, and doubled-brace placeholders, and that a value containing an ampersand, a backslash, or a percent sign survives.
- **IT-006**: Verify an untranslated key returns itself, can be marked, and stops the script only in strict mode.
- **IT-007**: Verify the predicate answers without recording a miss, and that a real miss is reported afterwards.
- **IT-008**: Verify the plural category of several counts in English, Vietnamese, French, Russian, Polish, and Arabic, including that Russian and Polish differ at twenty one.
- **IT-009**: Verify a plural lookup uses the rules of the catalog's language, falls back to `other`, then to a plain translation, and groups its count.
- **IT-010**: Verify the native format's comments, directives, quoting, quoted sentence keys, and missing final newline, and that a malformed entry stops the caller.
- **IT-011**: Verify the gettext format's continued strings, plural entries, contexts, and that fuzzy, obsolete, and empty entries are not translations.
- **IT-012**: Verify a hostile plural expression in a gettext header is never evaluated.
- **IT-013**: Verify catalog discovery in both directory layouts, that a file is loaded only once, and that resetting clears everything.
- **IT-014**: Verify grouping, rounding, carrying, padding, negative zero, leading zeros, and an integer wider than a machine word.
- **IT-015**: Verify number formatting is unchanged under a hostile numeric locale, and that an unknown locale falls back silently.
- **IT-016**: Verify currency decimal counts, symbol placement across locales, negative placement, accounting style, and the warning for an unknown code.
- **IT-017**: Verify byte sizes in both standards, the precision rule, localized digits with unlocalized units, and a value near the machine word limit.
- **IT-018**: Verify date and time styles across locales, literal quoting in a pattern, the twelve and twenty four hour clocks at midnight, and the timezone setting.
- **IT-019**: Verify names still come from the module when the shell's time locale is hostile.
- **IT-020**: Verify relative and duration spans in both directions, the singular case, count grouping, the environment reference time, and a translated relative string.
- **IT-021**: Verify direction reporting, isolation and stripping, and registering a further right-to-left language.
- **IT-022**: Verify each registration function is used by the formatters and rejects malformed input.
- **IT-023**: Verify extraction of literal keys, the report for a non-literal key, plural categories of the target language, context preservation, both output formats, and a round trip back through the loader.
- **IT-024**: Verify lint reports missing keys, empty translations, and differing placeholders, stays quiet on a complete translation, and does not report a plural-only key as missing.
- **IT-025**: Verify library diagnostics are English by default, translated when that is turned on, and passed through unchanged when untranslated.
- **IT-026**: Verify a keyed library string is English by default, is translated when that is turned on, fills the placeholders the translation uses, and keeps the English the call site built when the key is untranslated.
- **IT-027**: Verify a counted library string takes the target language's plural form, chooses between the forms a catalog declares, and keeps the English when the count is not a number.
- **IT-028**: Verify the success banner translates both its label and its message, that the progress and header banners are translated, and that all three are unchanged by default.
- **IT-029**: Verify generated help renders its headings and placeholders from the catalog, that a rejected switch is translated and still names the switch, and that both are English by default.
- **IT-030**: Verify both keyed hooks return their English argument in a child shell that never sourced the module.
- **IT-031**: In a script that loaded `i18n` alone, format a number and a relative time against a reference, have each date and time helper and a clock-relative time stop and name the `date` module, and format a date once `date` is loaded.
- **IT-032**: Have `i18n_percent` and `i18n_currency` stop on `abc` with no output and a message naming them, and `i18n_number` stop on a precision that is not an integer.
- **IT-033**: Load a catalog holding an empty key and report it under `dybatpho::i18n_load`.
- **IT-034**: Format a timestamp that is not a number with `i18n_datetime`; fail with no output and a message naming `i18n_datetime`.
- **IT-035**: Extract from a tree with an unreadable subdirectory and an unreadable file under errexit, and get the readable keys plus a warning for each gap.

## Acceptance Criteria *(mandatory)*

1. A script can present its messages, numbers, money, sizes, and dates in the reader's language, choosing plural forms by that language's rules.
2. The output depends only on the catalogs and the module's own data, never on which locales the machine happens to have generated or on its numeric locale.
3. Translations can be written and checked with the tools translators already use, and an incomplete one is reported rather than discovered by a user.
